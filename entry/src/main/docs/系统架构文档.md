# DayNote 系统架构文档

> **项目定位**：基于 HarmonyOS NEXT 的 2D/3D 交互通用技术框架，以笔记软件为载体展示沉浸式 3D 交互能力

---

## 一、项目概述

### 1.1 技术定位

DayNote 本质上是一个 **2D/3D 混合交互的通用技术框架**，笔记软件只是其首个应用场景。该框架的核心价值在于：

- **自研 3D 物理引擎**（C++ 实现，非第三方库依赖）
- **原生渲染层**（EGL + OpenGL ES 3.0）
- **ArkTS 3D 场景管理**（基于 @kit.ArkGraphics3D）
- **2D UI ↔ 3D 场景双向映射**
- **事件驱动架构**（优先级队列 + 双缓冲）

### 1.2 技术亮点

| 特性 | 实现方式 | 技术优势 |
|------|----------|----------|
| 物理模拟 | 自研 C++ 物理引擎 | 零依赖、可控、高性能 |
| 渲染性能 | SoA 数据布局 + FloatBuffer 共享内存 | 缓存友好、零拷贝 |
| 交互响应 | 事件优先级队列 + 自适应子步 | 触摸事件优先处理 |
| 2D/3D 融合 | UI ID ↔ Node ID 映射系统 | 2D 组件自动同步到 3D 空间 |
| 跨语言调用 | NAPI ObjectWrap 模式 | 类型安全、性能损耗低 |`n`n> 📚 **物理系统详细文档**：请参阅 [docs/physics/README.md](./physics/README.md) 获取物理系统的完整 API 使用说明和内部实现细节。

### 3.4 事件优先级队列设计

```
┌────────────────────────────────────────────────────────────┐
│                    EventCommand 结构                        │
│                                                            │
│  type: EventType        // 事件类型 (枚举)                  │
│  priority: number       // 优先级 (0=HIGH, 1=NORMAL, 2=LOW)│

优先级分类:
┌───────┬──────────────────────────────────────────────────┐
│ HIGH  │ TOUCH_DOWN, TOUCH_MOVE, TOUCH_UP,                │
│ (0)   │ BUTTON_TRIGGER, SET_PROPERTY_REQUEST             │
│       │ → 立即响应的交互事件                              │
├───────┼──────────────────────────────────────────────────┤

│       │ → 需要计算的事件                                  │
├───────┼──────────────────────────────────────────────────┤
│ LOW   │ RESET_GRAVITY, 动画事件                          │
│ (2)   │ → 后台处理的事件                                  │

┌──────────────┐         swap()        ┌──────────────┐

│  (新事件)     │                       │  (C++ 读取)   │
└──────────────┘                       └──────────────┘
     ↑                                       ↓
     │                                  处理并清空
     │
  每 20ms 调用 swapQueues()
```

```
│ pos_x[128] │ pos_y[128] │ pos_z[128]                   │
```

**技术优势**：
- 零拷贝：直接引用 C++ 分配的内存
- 缓存友好：SoA 布局提升 CPU 缓存命中率
- 批量更新：一次读取 128 个节点数据
- 性能：每帧更新 < 1ms

### 3.6 视差倾斜技术 (Parallax Tilt)

> 详见 `docs/视差倾斜原理详解.md`，此处展示核心思想

```
原理：物体在画面中的位置偏移会产生自然的倾斜效果

                    Camera (0, 0, -d)
                         ↓
                         │
                         │  视线方向 (offsetX, offsetY, d)
                         │ ↘
                         │  ╲
                         │   ╲ θy (Y轴倾斜角)
                         │    ╲
────────────────────────┼─────╲───────────────
                        │      ↓
                        │   Object
                        │  (offsetX, 0, 0)

核心公式：
  tiltX = atan2(offsetY, distance)    // X 轴倾斜
  tiltY = -atan2(offsetX, distance)   // Y 轴倾斜
  perspectiveFactor = tan(fovy/2) / distance

应用场景：
  - 卡片网格布局 (每个卡片根据位置自动倾斜)
  - 单卡片偏移效果 (移动时产生自然透视)
  - 组合旋转 (自身旋转 + 视差倾斜叠加)
```

### 3.7 自研物理引擎核心技术

#### 3.7.1 碰撞检测算法

```
┌────────────────────────────────────────────────────────────┐
│                    碰撞形状类型                             │
│                                                            │
│  SHAPE_SPHERE (球体)                                       │
│    - 存储: center(x,y,z) + radius                          │
│    - 检测: 距离比较 |p1 - p2| < r1 + r2                    │
│                                                            │
│  SHAPE_BOX (OBB - 定向包围盒)                              │
│    - 存储: center + extents(half-size) + orientation(矩阵)  │
│    - 检测: SAT (分离轴定理) - 15 个分离轴                   │
│      · 3 轴 (Box1 的法线)                                   │
│      · 3 轴 (Box2 的法线)                                   │
│      · 9 轴 (Box1×Box2 法线叉积)                           │
└────────────────────────────────────────────────────────────┘

射线检测 (Raycast)：
  - 射线-AABB: slab 方法 (快速剔除)
  - 射线-球体: 二次方程求解
  - 射线-OBB: 转换到局部空间后检测
```

#### 3.7.2 碰撞响应机制

```
冲量法求解接触点：

1. 检测碰撞 → 生成接触点 (Contact)
   - 碰撞法线 n
   - 穿透深度 penetration
   - 接触点位置 contactPoint

2. 计算相对速度 v_rel = v_B - v_A

3. 如果 v_rel · n < 0 (正在靠近)
   ↓
4. 计算冲量 j = -(1 + e) * v_rel · n
                ─────────────────────
                1/m_A + 1/m_B + ...

   e = 恢复系数 (restitution)

5. 应用冲量到线速度和角速度
   v_A -= j * n / m_A
   ω_A -= I_A^-1 * (contactPoint × j*n)

6. 位置修正 (防止穿透)
   position_A -= penetration * n * 0.5
```

#### 3.7.3 自适应子步长

```
问题：快速移动物体可能在一帧内穿过障碍物

解决方案：
  subSteps = max(1, |velocity| * dt / minExtent)
  subSteps = min(subSteps, 8)  // 限制最大 8 步

  dt_sub = dt / subSteps
  
  for (i = 0; i < subSteps; i++) {
    integrate(dt_sub)
    detectCollisions()
    resolveCollisions()
  }

效果：
  - 慢速物体: 1 子步 (高效)
  - 快速物体: 多子步 (精确)
  - 防止穿透: 速度钳制
```

### 9.3 核心技术描述模板

```
【技术名称】2D UI ↔ 3D Node 双向映射技术

【解决的问题】
传统 2D UI 无法与 3D 场景交互，需要手动同步位置和状态。

【技术方案】
1. 建立 uiId → nodeId 映射表
2. 2D UI 位置变化时自动同步到 3D 物理节点
3. 3D 物理模拟结果实时影响 2D UI 显示

【关键实现】
- 映射注册：registerUI2DTo3D(uiId, nodeId)
- 位置同步：syncUIto3D(uiId, x, y, z)
- 事件驱动：触摸事件通过射线检测选中 3D 节点

【性能优势】
- 零拷贝：FloatBuffer 直接引用 C++ 内存
- 批量更新：每帧更新 128 个节点 < 1ms
- 自动同步：无需手动管理位置

【可应用场景】
- 2D/3D 混合笔记应用 (当前)
- 交互式产品展示
- 2D UI 控制 3D 场景
- 物理教学演示
```
