## 2. 公共技术能力（所有功能的基础）

> 本节列出所有功能共用的底层融合能力，后续各功能模块通过引用本节编号来避免重复描述。

### 2.1 空间坐标体系

系统涉及三套坐标系，所有空间操作都基于它们之间的转换：

| 坐标系 | 名称 | 原点 | 轴向 | 单位 |
|--------|------|------|------|------|
| **世界坐标系** (World) | 3D 场景空间 | 场景中心 (0,0,0) | X 右 / Y 上 / Z 朝向相机（负值） | 场景单位 |
| **屏幕坐标系** (Screen) | ArkUI 2D 视图 | 屏幕左上角 (0,0) | X 右 / Y 下 | vp (虚拟像素) |
| **卡片局部坐标系** (Local) | 笔记卡片自身空间 | 卡片中心 (0,0) | X 右 / Y 上 | 像素 |

**坐标转换接口**：
```typescript
// 屏幕坐标 → NDC 归一化坐标（用于射线检测）
// 文件: ets/core/scene3D/GlobalSceneProxy.ets
fx = (2 * ui.vp2px(pos.x) / sceneSize.width) - 1;   // 范围 [-1, 1]
fy = 1 - (2 * ui.vp2px(pos.y) / sceneSize.height);   // Y 轴翻转
```

**锚定方式**：
- 2D 笔记卡片使用屏幕坐标系定位
- 3D 替身节点使用世界坐标系，通过 `uiToNodeIdMap` 与 2D 卡片关联
- 笔记面板的默认锚定：世界绝对位置（通过 `addUIPlane` 创建后显式设置 position）

### 2.2 射线-模型交互基础

用于 3D 测试场景和空间拾取的核心能力。

**交互流程**：
```
用户触摸屏幕 (2D)
    │
    ▼ 屏幕坐标 → NDC 转换
┌─────────────────────────────────────┐
│  射线构建: origin=相机位置,          │
│           dir = 归一化视线方向       │
│  virtual_pos = (up*fy + right*fx*ratio) * (-z * tan(fov/2))
│  rayDir = (virtual_pos - cameraPos).normalized()
└──────────────────┬──────────────────┘
                   ▼
┌─────────────────────────────────────┐
│  遍历所有物理节点，按 shapeType 选择: │
│  • AABB/OBB → raycastOBB()          │
│  • Sphere   → raycastSphere()        │
│  返回最近命中: nodeId + distance     │
└──────────────────┬──────────────────┘
                   ▼
┌─────────────────────────────────────┐
│  EventResult 返回 ArkTS 侧           │
│  → selectId = 命中节点 ID            │
│  → 支持拖拽旋转等后续操作             │
└─────────────────────────────────────┘
```

**三类射线检测算法**：

| 算法 | 文件 | 适用场景 | 性能 |
|------|------|----------|------|
| `raycastAABB` | `raycast.h` | 未旋转包围盒 | 最快 (slab 方法) |
| `raycastOBB` | `raycast.h` | 旋转后包围盒 | 中 (局部变换+slab) |
| `raycastSphere` | `raycast.h` | 球形包围盒 | 快 (二次方程) |

**返回值**：命中节点 ID、命中距离、命中点世界坐标。

### 2.3 空间索引服务

**功能**：按相机视野范围快速查询 3D 节点位置，支持随机生成新节点的合法位置。

**核心接口**（`ets/core/scene3D/layout/CameraViewUtils.ets`）：

```typescript
// 计算相机在指定 Z 距离的视野范围
getCameraFrustumAtZ(config: CameraConfig, z: number): FrustumBounds

// 在相机视野内生成随机位置（不与已有位置重叠）
getRandomPositionInCameraView(config: CameraConfig, occupied: Vec3[]): Vec3

// 生成多个不重叠的随机位置
getMultipleRandomPositionsInCameraView(config: CameraConfig, count: number): Vec3[]

// 检查点是否在相机视野内
isPointInCameraView(point: Vec3, config: CameraConfig): boolean
```

**实现原理**：
- 基于相机 FOV、宽高比、近/远裁剪面计算视锥体截面
- 随机位置通过均匀采样 + 重叠检测生成

**当前状态**：🔧 工具函数已实现，完整的 LayoutSystem（网格/列表/堆叠布局）处于 📐 设计阶段（见 `LayoutSystemDesign.md`）。

### 2.4 纹理与卡片渲染管理

**功能**：管理笔记卡片的 2D 渲染与 3D 替身外观。

**双渲染管线**：

```
┌──────────────────────┐     ┌──────────────────────┐
│  2D ArkUI 渲染管线    │     │  3D ArkGraphics3D    │
│                      │     │                      │
│  • RichEditor 富文本  │     │  • Plane 替身节点     │
│  • 文本/图片 Spans   │     │  • 自定义 Shader      │
│  • 触摸事件响应       │     │  • 阴影/光照/后处理    │
│  • 卡片 3D 倾斜效果   │     │  • 碰撞体 (AABB)      │
└──────────────────────┘     └──────────────────────┘
         │                            │
         └────── 数据同步 ─────────────┘
              位置/旋转/缩放/可见性
```

**卡片渲染关键点**：
- 2D 卡片使用 `RichEditor` 组件渲染富文本内容
- 3D 替身节点使用 Plane 几何体，可通过自定义 Shader 绑定纹理
- 卡片支持伪 3D 倾斜效果（透视变换矩阵，见 2.6）

**性能约束**：
- 卡片列表中的预览模式仅加载前 3 个 Span（简化渲染）
- 完整版加载所有 Span（编辑器模式）
- 图片默认尺寸 425×325，预览模式压缩为最大边 80px

### 2.5 融合实体生命周期

**定义**：融合实体指 2D 笔记卡片与其 3D 替身节点组成的统一逻辑对象。

**生命周期阶段**：

| 阶段 | 触发条件 | 操作内容 | 关联模块 |
|------|----------|----------|----------|
| **创建** | 用户新建笔记/快速记录 | 1. 创建 2D 卡片 UI<br>2. 调用 `addUIPlane()` 创建 3D 替身<br>3. 注册 `uiToNodeIdMap` 映射 | SceneProxy, NoteViewModel |
| **附着** | 卡片定位到日期/空间位置 | 1. 设置 2D 卡片在列表中的位置<br>2. 设置 3D 替身的 position/scale<br>3. 设置物理属性（静态/动态） | mainDisplay, PhysicsSystemManager |
| **更新** | 编辑内容/拖动位置 | 1. 2D 卡片内容刷新<br>2. FloatBuffer 同步位置/旋转/缩放<br>3. 3D 场景渲染更新 | EditorController, EventQueueManager |
| **分离** | 删除笔记 | 1. 从卡片列表移除<br>2. 从物理系统 removeNode<br>3. 清理映射表 | NoteViewModel, PhysicsSystemManager |
| **销毁** | 物理资源回收 | 1. 销毁纹理<br>2. 释放 FloatBuffer 条目到空闲列表<br>3. 删除文件/数据库记录 | PhysicsSystem, NoteService |

### 2.6 卡片 3D 倾斜变换

**功能**：为 2D 卡片组件添加基于触摸位置的伪 3D 透视倾斜效果。

**实现原理**（`entryCard.ets` 的 `getTiltMatrix()`）：

```typescript
// 根据触摸位置计算旋转角度
// 最大倾斜角 15 度
const maxTilt = 15;
const tiltX = -touchY / cardHeight * maxTilt;
const tiltY = touchX / cardWidth * maxTilt;

// 4×4 透视变换矩阵
// 透视因子 = 2000
const perspective = 2000;
```

**效果**：
- 触摸卡片边缘时产生向内倾斜的视觉效果
- 阴影随倾斜角度动态偏移（`uiShadow()` 方法）
- 该效果纯 2D matrix4 变换，不依赖 3D 场景渲染

## 3. 功能模块一：笔记管理

### 3.1 创建笔记 ✅

笔记支持两种创建方式，对应不同的使用场景。

#### 3.1.1 方式 A：快速记录（NOTE 类型）

**用户操作**：
1. 在主页面底部输入框中输入文字
2. 点击发送按钮（右侧箭头图标）

**交互流程**：
```
用户输入文字
    │
    ▼
RichEditor 捕获内容（最多 5 行）
    │
    ▼
点击发送按钮
    │
    ▼
┌─────────────────────────────────────┐
│ NoteViewModel.newNote(NOTE)         │
│ → 生成 ID: note_YYYY_MM_DD_HH_mm_ss │
│ → 创建目录: {baseDir}/YYYY/MM/DD/   │
└──────────────┬──────────────────────┘
               ▼
┌─────────────────────────────────────┐
│ NoteViewModel.saveNote()            │
│ → 提取 Spans → NoteSpanData[]       │
│ → 序列化 JSON → 写入文件            │
│ → 不写入数据库（NOTE 类型仅文件存储） │
└──────────────┬──────────────────────┘
               ▼
┌─────────────────────────────────────┐
│ 清空编辑器                          │
│ 触发 needsFreshNotes = true          │
│ mainDisplay.refreshNotes()          │
│ → 扫描目录发现新文件                 │
│ → 卡片出现动画 (500ms)               │
└─────────────────────────────────────┘
```

**技术依赖**：公共 2.5（融合实体创建流程）

**边界与约束**：
- 内容为空时点击发送：不创建笔记
- 文件名格式：`{noteId}.json`
- 目录结构：`{baseDir}/{year}/{month}/{day}/`

#### 3.1.2 方式 B：完整编辑（ARTICLE 类型）

**用户操作**：
1. 点击主页底部 `+` 按钮
2. 弹出菜单中选择"编辑"
3. 跳转到笔记编辑页面（NotePage）

**交互流程**：
```
+ 按钮 → 弹出菜单 → 选择"编辑"
    │
    ▼
router.pushUrl("pages/NotePage", { action: NEW })
    │
    ▼
┌─────────────────────────────────────┐
│ NotePage.onPageShow                 │
│ → NoteViewModel.newNote(ARTICLE)    │
│ → 生成 ID + 创建目录                 │
└──────────────┬──────────────────────┘
               ▼
┌─────────────────────────────────────┐
│ 用户编辑内容：                        │
│ • 富文本（粗体/斜体/下划线/颜色）      │
│ • 插入图片                           │
│ • 编辑标题                           │
└──────────────┬──────────────────────┘
               ▼
┌─────────────────────────────────────┐
│ 点击保存按钮                          │
│ → saveNote()                        │
│ → 序列化内容 → 写入 JSON 文件        │
│ → syncNoteToDatabase()              │
│   → InsertNote() → NOTES 表         │
│   → 返回 rowId → setDbId()          │
└─────────────────────────────────────┘
```

**技术依赖**：公共 2.4（卡片渲染）、公共 2.5（融合实体创建流程）

**边界与约束**：
- 标题默认值："无标题"
- 标题最大 1 行（TextInput singleLine）
- RichEditor placeholder："开始记录您的想法..."

**边界与约束**：
- 加载 ARTICLE 类型笔记时，从数据库获取文件路径
- 图片插入默认尺寸 425×325，圆角 8px，边距 10px

**交互流程**：
```
┌─────────────────────────────────────┐
│ mainDisplay.getNotes(timestamp)     │

│ → NoteService.getNoteList(dir)      │
```

### 6.1 笔记保存与加载 ✅

**数据模型**：

系统采用**双类型笔记系统**，不同类别使用不同的存储策略：

| 类型 | 枚举值 | 存储方式 | 显示位置 | 用途 |
|------|--------|----------|----------|------|

| **ARTICLE** | 2 | JSON 文件 + RDB 数据库 | 数据库查询/编辑 | 完整笔记、长文章 |

**序列化格式**（JSON）：
```json
{
  "id": "note_2026_05_10_14_30_00",
  "title": "无标题",
  "type": 2,
  "content": [
    {
      "type": "text",
      "id": "span_001",
      "content": "这是一条笔记内容",
      "style": {
        "fontSize": 16,
        "fontColor": "black",
        "fontWeight": "normal",
        "fontStyle": "normal"
      },
      "timestamp": 1715326200000
    },
    {
      "type": "image_local",
      "id": "span_002",
      "content": "",
      "imageInfo": {
        "localPath": "/data/.../images/span_002.png",
        "width": 425,
        "height": 325
      },
      "timestamp": 1715326200000
    }
  ]
}
```

```

│                                     │
│ 3. 序列化 JSON                       │
│    JSON.stringify(NoteData)          │
│                                     │
│ 4. 写入文件                          │
│    writeStringToFile({dir}/{id}.json)│
│                                     │
│ 5. 清理未使用的图片文件              │
│    扫描 images/ 目录，比对引用关系    │
│                                     │
│ 6. 如果是 ARTICLE 类型:             │
│    syncNoteToDatabase()              │
```
