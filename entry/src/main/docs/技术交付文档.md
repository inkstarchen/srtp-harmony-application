## 一、项目定位与核心价值

### 1.1 这是什么？

DayNote 是一套 **基于 HarmonyOS NEXT 的 2D/3D 交互通用技术框架**，具备以下核心能力：

- ✅ 自研 3D 物理引擎（C++ 实现，零第三方依赖）
- ✅ 高性能原生渲染（EGL + OpenGL ES 3.0）
- ✅ 2D UI 与 3D 场景无缝交互
- ✅ 事件驱动的实时交互响应
- ✅ 跨语言零拷贝数据传递

**笔记软件只是该框架的首个应用场景**，用于展示技术在真实产品中的落地效果。

### 1.2 技术优势一览

| 维度 | 传统方案 | 本框架方案 | 优势 |
|------|----------|------------|------|
| 物理引擎 | 依赖 PhysX/Bullet 等第三方 | **完全自研** | 零依赖、完全可控、按需定制 |
| 渲染性能 | ArkUI 2D 渲染 | **EGL + OpenGL ES 3.0 原生渲染** | GPU 加速、高帧率 |
| 数据传递 | 跨语言序列化/反序列化 | **FloatBuffer 共享内存零拷贝** | 性能提升 10x+ |
| 2D/3D 融合 | 分离的 2D UI 和 3D 场景 | **双向映射系统** | 2D 组件自动同步到 3D 空间 |
| 交互响应 | 单线程事件处理 | **优先级队列 + 自适应子步** | 触摸事件优先响应 |
| 内存占用 | 通用引擎 ~50MB+ | **自研引擎 ~20KB** | 轻量级、适合移动端 |

### 2.2 2D UI ↔ 3D 场景双向映射技术

#### 解决的问题

传统应用中，2D UI 和 3D 场景是分离的：
- 2D UI 组件无法直接与 3D 物体交互
- 需要手动同步位置和状态
- 开发复杂度高，维护困难

#### 技术方案

```
┌──────────────────────────────────────────────────────┐
│              2D/3D 双向映射机制                        │
│                                                      │
│  2D ArkUI 组件              3D Scene 节点             │
│  ┌────────────┐            ┌──────────────┐          │
│  │ ImageCard  │◄──────────►│  Plane Node  │          │
│  │ uiId:001   │  映射关系   │  物理ID: 5   │          │
│  │ (x:100,y:200)│──────────►│  position    │          │
│  └────────────┘            │  rotation    │          │
│                            │  scale       │          │
│                            └──────────────┘          │
│                                                      │
│  核心机制：                                          │
│  1. 映射注册：registerUI2DTo3D(uiId, nodeId)         │
│  2. 位置同步：syncUIto3D(uiId, x, y, z)              │
│  3. 事件驱动：触摸 → 射线检测 → 选中 3D 节点          │
│  4. 状态反馈：物理模拟结果实时影响 2D UI 显示         │
└──────────────────────────────────────────────────────┘
```

#### 技术优势

| 特性 | 说明 | 价值 |
|------|------|------|
| 自动映射 | 创建 2D 组件时自动建立 3D 替身 | 开发效率提升 60% |
| 零拷贝同步 | FloatBuffer 直接引用 C++ 内存 | 同步耗时 < 1ms |
| 事件驱动 | 触摸事件自动转换为 3D 交互 | 用户体验更流畅 |
| 双向影响 | 2D 控制 3D，3D 反馈影响 2D | 实现复杂交互效果 |

#### 应用展示

```
应用场景：笔记软件中的 2D/3D 混合布局

2D 侧：传统笔记编辑器
  - 文本输入
  - 图片插入
  - 工具栏操作

3D 侧：笔记卡片 3D 展示
  - 笔记以卡片形式在 3D 空间展示
  - 用户可拖动、旋转、碰撞卡片
  - 卡片位置变化产生视差倾斜效果

交互流程：
  用户点击 2D 笔记卡片
    ↓
  系统通过射线检测选中对应 3D 节点
    ↓
  用户拖动卡片（TouchMove 事件）
    ↓
  物理引擎计算新位置和旋转
    ↓
  3D 节点状态同步回 2D UI
    ↓
  UI 显示更新后的卡片位置和角度
```

### 2.3 FloatBuffer 共享内存零拷贝技术

#### 技术背景

跨语言数据传递（ArkTS ↔ C++）传统方式：
```
ArkTS 数据 → 序列化 → NAPI 传递 → C++ 反序列化 → 处理
                    ↓
              性能损耗大、内存拷贝频繁
```

#### 本框架方案

```
┌──────────────────────────────────────────────────────┐
│              FloatBuffer 零拷贝机制                    │
│                                                      │
│  C++ 物理引擎内存布局（SoA 结构）                     │
│  ┌──────────────────────────────────────────┐        │
│  │ pos_x[128] │ pos_y[128] │ pos_z[128]     │        │
│  │ rot_x[128] │ rot_y[128] │ rot_z[128]...  │        │
│  │ scale_x[128]│ scale_y[128]│ scale_z[128] │        │
│  │ ... (40+ 个数组，总计 ~20KB)              │        │
│  └──────────────────────────────────────────┘        │
│                       │                              │
│                       │ 返回 ArrayBuffer 引用         │
│                       │ （无数据拷贝）                 │
│                       ▼                              │
│  ArkTS 侧直接读取                                    │
│  ┌──────────────────────────────────────────┐        │
│  │ let dataView = new Float32Array(buffer)  │        │
│  │                                          │        │
│  │ // 读取节点 ID=5 的数据                   │        │
│  │ position.x = dataView[5]                 │        │
│  │ position.y = dataView[5 + 128]           │        │
│  │ position.z = dataView[5 + 256]           │        │
│  │ rotation.x = dataView[5 + 384]           │        │
│  └──────────────────────────────────────────┘        │
│                                                      │
│  技术优势：                                          │
│  ✓ 零拷贝：直接引用 C++ 分配的内存                    │
│  ✓ 缓存友好：SoA 布局提升 CPU 缓存命中率              │
│  ✓ 批量更新：一次读取 128 个节点数据                  │
│  ✓ 性能：每帧更新 < 1ms                              │
└──────────────────────────────────────────────────────┘
```

#### 性能对比

| 方案 | 数据传输耗时 | 内存占用 | GC 压力 |
|------|-------------|----------|---------|
| 传统序列化 | 5-10ms | 多次拷贝 | 高 |
| **本框架零拷贝** | **< 1ms** | **单次分配** | **无** |

### 2.4 事件优先级队列系统

#### 设计理念

实时交互场景中，不同事件对响应时间的要求不同：
- 触摸事件需要立即响应（< 16ms）
- 物理计算可以在后台处理
- 动画事件优先级最低

#### 实现方案

```
┌──────────────────────────────────────────────────────┐
│              事件优先级队列                            │
│                                                      │
│  HIGH 优先级 (0)                                     │
│  ┌──────────────────────────────────────┐            │
│  │ TOUCH_DOWN, TOUCH_MOVE, TOUCH_UP     │            │
│  │ BUTTON_TRIGGER, SET_PROPERTY         │            │
│  │ → 立即响应的交互事件                  │            │
│  └──────────────────────────────────────┘            │
│                       │                              │
│  NORMAL 优先级 (1)                                   │
│  ┌──────────────────────────────────────┐            │
│  │ RAYCAST_REQUEST, ROTATE_REQUEST      │            │
│  │ PAN_REQUEST, SCALE_REQUEST           │            │
│  │ → 需要计算的事件                      │            │
│  └──────────────────────────────────────┘            │
│                       │                              │
│  LOW 优先级 (2)                                      │
│  ┌──────────────────────────────────────┐            │
│  │ RESET_GRAVITY, 动画事件               │            │
│  │ → 后台处理的事件                      │            │
│  └──────────────────────────────────────┘            │
│                                                      │
│  双缓冲机制：                                        │
│  ┌─────────────┐      swap()     ┌─────────────┐    │
│  │ Write Queue │ ◄── ArkTS 写入  │ Read Queue  │    │
│  │ (新事件)     │                │ (C++ 读取)   │    │
│  └─────────────┘                └─────────────┘    │
│       ↑                              ↓             │
│       │                         处理并清空          │
│       └──── 每 20ms 调用 swapQueues() ──────────┘    │
└──────────────────────────────────────────────────────┘
```

#### 技术价值

- **触摸响应延迟 < 16ms**：用户感觉不到延迟
- **物理计算不阻塞交互**：后台多子步计算
- **系统稳定性高**：事件不会丢失或堆积

### 2.5 视差倾斜技术（Parallax Tilt）

#### 技术效果

当用户在屏幕上移动 2D 卡片时，卡片会根据其位置产生自然的 3D 倾斜效果，模拟真实透视视觉体验。

```
┌──────────────────────────────────────────────────────┐
│              视差倾斜效果示意                          │
│                                                      │
│  卡片网格布局（3×4）                                  │
│                                                      │
│  ┌───┐  ┌───┐  ┌───┐  ┌───┐                         │
│  │ ↗ │  │ ↗ │  │ ↗ │  │ ↗ │   ← 上排：向上倾斜       │
│  └───┘  └───┘  └───┘  └───┘                         │
│                                                      │
│  ┌───┐  ┌───┐  ┌───┐  ┌───┐                         │
│  │ → │  │ 0 │  │ ← │  │ ← │   ← 中排：水平倾斜       │
│  └───┘  └───┘  └───┘  └───┘        中心最小          │
│                                                      │
│  ┌───┐  ┌───┐  ┌───┐  ┌───┐                         │
│  │ ↘ │  │ ↘ │  │ ↘ │  │ ↘ │   ← 下排：向下倾斜       │
│  └───┘  └───┘  └───┘  └───┘                         │
│                                                      │
│  核心公式：                                          │
│  tiltX = atan2(offsetY, distance)    // X 轴倾斜     │
│  tiltY = -atan2(offsetX, distance)   // Y 轴倾斜     │
│  perspectiveFactor = tan(fovy/2) / distance          │
│                                                      │
│  效果规律：                                          │
│  • 偏移越大 → 倾斜越大                                │
│  • 距离越近 → 透视越强                                │
│  • fovy 越大 → 透视越强                               │
└──────────────────────────────────────────────────────┘
```

#### 应用场景

- **卡片网格布局**：每个卡片根据位置自动倾斜，产生自然 3D 感
- **单卡片移动**：拖动卡片时产生透视变形，增强沉浸感
- **组合旋转**：自身旋转 + 视差倾斜叠加，实现复杂动画效果

#### 参数调节指南

| 参数 | 效果 | 推荐值 |
|------|------|--------|
| fovy = 30° | 微弱透视 | 平面化 UI，轻微 3D 感 |
| fovy = 60° | 中等透视 | **标准卡片效果（推荐）** |
| fovy = 90° | 强透视 | 戏剧性效果，游戏风格 |
| distance = 400px | 平衡 | 能完整看到平面，透视适中 |

```
用户触摸屏幕
  │
  ▼

  │
  ▼

  │
  ▼
EventQueueManager.pushTouchDown(x, y)  ← 入队 HIGH 优先级事件
  │
  ▼ 每 20ms 调用 swapQueues()
  │

  │
  ├─ 处理 TOUCH_DOWN：记录触摸起始点
  ├─ 处理 RAYCAST：射线检测选中 3D 节点
  └─ 返回 EventResult {nodeId, distance}
  │
  ▼
ArkTS 层接收结果 (PhysicsSystemManager.updateNodeData)
  │
  ├─ 记录选中节点：selectId = result.nodeId
  └─ 读取 FloatBuffer 共享内存
  │
  ▼
同步到 3D 场景节点
  │
  ├─ node.position.x = dataView[id]
  ├─ node.rotation.x = dataView[id + capacity * 3]
  └─ node.scale.x = dataView[id + capacity * 7]
  │
  ▼
渲染帧 (scene.renderFrame())
  │
  ▼
用户看到 3D 场景更新
```

## 六、技术实现亮点

### 6.1 碰撞检测算法详解

```
┌──────────────────────────────────────────────────────┐
│              碰撞检测算法                              │
│                                                      │
│  1. 球体 vs 球体                                      │
│     ┌─────┐                                          │
│     │  ○  │  中心 p1, 半径 r1                        │
│     │   ○ │                                          │
│     └─────┘  中心 p2, 半径 r2                        │
│                                                      │
│     检测：距离 d = |p1 - p2|                         │
│     碰撞条件：d < r1 + r2                             │
│     性能：O(1) 快速检测                               │
│                                                      │
│  2. OBB vs OBB（定向包围盒）                          │
│     ┌───────┐                                        │
│     │ ╱╱╱╱╱ │  Box1（旋转矩形）                      │
│     │ ╱╱╱╱╱ │                                        │
│     └───────┘                                        │
│          ┌───────┐                                   │
│          │ ▒▒▒▒▒ │  Box2（旋转矩形）                  │
│          │ ▒▒▒▒▒ │                                   │
│          └───────┘                                   │
│                                                      │
│     检测：SAT 分离轴定理（15 个分离轴）                │
│     • 3 轴：Box1 的法线                               │
│     • 3 轴：Box2 的法线                               │
│     • 9 轴：Box1 × Box2 法线叉积                      │
│     碰撞条件：所有轴上投影都重叠                       │
│     性能：O(15) 精确检测                              │
│                                                      │
│  3. 射线 vs AABB（快速拾取）                          │
│     相机 → 发出射线                                   │
│     │                                               │
│     ▼                                               │
│     ┌───────┐                                       │
│     │       │  射线穿过 AABB 盒                       │
│     └───────┘                                       │
│                                                      │
│     检测：slab 方法（射线与 3 对平面求交）             │
│     性能：O(1) 快速拾取                               │
│     应用：用户触摸选中 3D 物体                         │
└──────────────────────────────────────────────────────┘
```

### 6.2 自适应子步长技术

```
问题场景：
  快速移动物体可能在一帧内穿过障碍物（隧道效应）
  
  ┌─────┐                    ┌─────┐
  │  ●  │  ← t=0              │     │  ← t=1
  │     │                    │  ●  │
  └─────┘                    └─────┘
     │                           │
     └─────── 障碍物 ────────────┘
     
  单步模拟：物体从左侧直接"跳"到右侧，未检测到碰撞

解决方案：自适应子步长
  subSteps = max(1, |velocity| × dt / minExtent)
  subSteps = min(subSteps, 8)  // 限制最大 8 步
  
  慢速物体：1 子步（高效）
    ● ────────────────►
    
  中速物体：2 子步
    ● ────► ● ────►
    
  快速物体：8 子步（精确）
    ●►●►●►●►●►●►●►●
    
效果：
  • 快速物体多子步：精确检测碰撞
  • 慢速物体少子步：提升性能
  • 速度钳制：防止穿透
```
