## 1. 引言

### 1.1 文档目的

本文档聚焦于 **2D/3D融合可视化引擎** 的架构设计，详述系统的分层结构、核心技术模块及其交互关系。需要明确指出：**笔记功能仅是该技术的验证载体**，本文档的核心关注点是融合引擎本身——即如何在 HarmonyOS NEXT 平台上实现 2D UI 与 3D 场景的无缝交互。

文档面向以下读者：
- 引擎架构设计者与核心开发者
- 物理系统/渲染管线的维护者
- 需要在该项目基础上扩展 2D/3D 交互功能的开发者

### 1.2 核心能力定位

本系统的核心竞争力并非笔记业务逻辑，而是以下三项技术能力的有机结合：

| 能力维度 | 描述 | 技术关键词 |
|----------|------|------------|
| **2D/3D空间一致性** | 2D UI 组件在 3D 世界中拥有精确的空间映射，坐标、旋转、缩放双向同步 | 坐标变换矩阵、PerspectiveTransform、UI2D↔3D映射 |
| **混合渲染** | 2D 原生渲染（ArkUI）与 3D 渲染（ArkGraphics3D）共存，共享阴影与光照效果 | 替身节点（Proxy Node）、自定义 Shader、图层同步 |
| **双向交互** | 用户通过 2D 触摸操作 3D 物体，3D 物理模拟结果反过来影响 2D 布局 | 射线检测、事件队列、NAPI SoA 物理引擎 |

这三项能力构成了一套 **可复用的 2D/3D 交互通用框架**，可应用于产品展示、沉浸式教学、空间数据可视化等多个领域。

## 3. 核心技术一：2D/3D空间一致性建模

### 3.1 坐标系统设计

系统涉及三套坐标系，它们之间的精确映射是 2D/3D 融合的基础：

#### 3.1.1 坐标系定义

| 坐标系 | 名称 | 原点 | 轴向 | 单位 |
|--------|------|------|------|------|
| **世界坐标系** (World Space) | 3D 场景空间 | 场景中心 (0,0,0) | X 右 / Y 上 / Z 朝向相机（负值） | 场景单位 |
| **屏幕坐标系** (Screen Space) | ArkUI 2D 视图 | 屏幕左上角 (0,0) | X 右 / Y 下 | vp (虚拟像素) |
| **笔记平面坐标系** (Plane Space) | 笔记卡片局部空间 | 卡片中心 (0,0) | X 右 / Y 上 | 像素 |

#### 3.1.2 屏幕坐标 → 3D 视锥体坐标转换

在射线检测中，需要将 2D 屏幕坐标转换为 3D 视锥体中的归一化设备坐标 (NDC)：

```typescript
// 文件: ets/core/scene3D/GlobalSceneProxy.ets - rayCast()
// 屏幕坐标 (vp) → 归一化视锥体坐标 [-1, 1]
let fx = (2 * ui.vp2px(pos.x) / SceneProxy.sceneSize.width) - 1;   // 范围 [-1, 1]
let fy = 1 - (2 * ui.vp2px(pos.y) / SceneProxy.sceneSize.height);   // 范围 [-1, 1]，Y 轴翻转
```

转换公式的几何含义：
- `fx = -1` 对应屏幕左边缘，`fx = +1` 对应屏幕右边缘
- `fy = +1` 对应屏幕上边缘，`fy = -1` 对应屏幕下边缘
- 这个归一化坐标用于构建从相机出发的射线方向向量

#### 3.1.3 射线方向向量构建

```cpp
// 文件: cpp/physics/physics/physicalSystem.cpp - processRaycast()
// 构建虚拟平面上的射线目标点
Vector3 virtual_pos = (up * touchY + right * touchX * ratio) * (-cameraPos.z * tan(fov/2));
Vector3 rayDir = (virtual_pos - cameraPos).normalized();
```

其中：
- `up`、`right` 为相机局部坐标的上方向和右方向向量
- `ratio` 为屏幕宽高比
- `-cameraPos.z * tan(fov/2)` 将 NDC 坐标缩放到视锥体截面尺寸

### 3.2 2D内容在3D空间中的定位模型

#### 3.2.1 UI 替身节点 (Proxy Node)

系统在 3D 场景中为每个 2D UI 组件创建一个对应的 **平面替身节点**。该节点具备以下特性：

| 属性 | 描述 |
|------|------|
| **几何体** | Plane（平面网格），尺寸与 2D UI 组件对应 |
| **位置** | 由 2D UI 的屏幕坐标通过坐标映射计算得到 |
| **朝向** | 可配置：固定朝向（始终面向相机）或跟随相机（产生视差） |
| **物理属性** | 可静态（仅碰撞）或动态（受物理引擎控制） |
| **渲染** | 透明或自定义 Shader 材质，用于接收/投射阴影 |

#### 3.2.2 两种 UI 替身模式

系统提供两种替身创建模式，对应不同的使用场景：

**模式一：静态 UI 替身 (`addUIPlane`)**

```typescript
// 文件: ets/core/scene3D/GlobalSceneProxy.ets
async addUIPlane(name: string, scale: Vec2): Promise<number | undefined> {
  let nodeId = await this.addNodeWithScaleReturnId('card', 'Plane', name, scale);
  if (nodeId !== undefined) {
    this.registerUI2DTo3D(name, nodeId); // 注册 2D→3D 映射
  }
  return nodeId;
}
```

- 适用于：固定位置的 UI 元素（如标题栏、静态卡片）
- 物理属性：默认为静态节点 (`isStatic = true`)
- 位置控制：通过 `syncUIto3D()` 显式同步

**模式二：动态 UI 替身 (`addDynamicUIPlane`)**

```typescript
async addDynamicUIPlane(name: string, scale: Vec2): Promise<number | undefined> {
  let nodeId = await this.addNodeWithScaleReturnId('card', 'Plane', name, scale);
  if (nodeId !== undefined) {
    this.registerUI2DTo3D(name, nodeId);
    this.eventQueue.setStatic(nodeId, false); // 设置为动态
    this.eventQueue.setMass(nodeId, 1.0);     // 设置质量
  }
  return nodeId;
}
```

- 适用于：需要物理交互的 UI 元素（如可拖拽卡片、物理下落效果）
- 物理属性：动态节点，受重力和碰撞影响
- 位置控制：由物理引擎 `PhysicsSystem` 驱动

#### 3.2.3 2D→3D 映射注册表

```typescript
// 文件: ets/core/scene3D/GlobalSceneProxy.ets
private uiToNodeIdMap: Map<string, number> = new Map();

registerUI2DTo3D(uiId: string, nodeId: number) {
  this.uiToNodeIdMap.set(uiId, nodeId);
}

get3DNodeId(uiId: string): number | undefined {
  return this.uiToNodeIdMap.get(uiId);
}
```

映射表维护 2D UI 标识符到 3D 物理节点 ID 的双向查找能力，是跨系统数据同步的纽带。

### 3.3 纹理共享机制

#### 3.3.1 跨阶段复用原理

2D UI 内容（文本、图片、富文本）由 ArkUI 渲染管线绘制到屏幕帧缓冲区，而 3D 场景由 ArkGraphics3D 管线独立渲染。为实现 2D 内容在 3D 空间中的可视化呈现，系统采用 **替身节点同步** 而非直接的纹理共享：

```
┌──────────────────┐              ┌──────────────────┐
│  ArkUI 2D 渲染   │              │  ArkGraphics3D    │
│                  │              │                  │
│  ┌────────────┐  │   坐标同步   │  ┌────────────┐  │
│  │  UI 组件   │──┼───位置 ────►│  │  Proxy     │  │
│  │  (真实)    │  │   旋转同步   │  │  Plane     │  │
│  │            │  │   缩放同步   │  │  (替身)    │  │
│  └────────────┘  │              │  └────────────┘  │
└──────────────────┘              └──────────────────┘
       ▲                                  ▲
       │                                  │
       │         用户视觉感知              │
       └──────────────────────────────────┘
```

#### 3.3.2 同步数据结构 (FloatBuffer SoA)

C++ 物理引擎使用 **Structure of Arrays (SoA)** 内存布局存储所有节点的状态，通过 FloatBuffer 在 C++ 与 ArkTS 之间零拷贝传输：

```
FloatBuffer 内存布局（128 节点容量，总计约 20KB）

偏移范围        数据内容                    说明
────────────────────────────────────────────────────
0~127          pos_x[128]                 X 位置
128~255        pos_y[128]                 Y 位置
256~383        pos_z[128]                 Z 位置
384~511        rot_x[128]                 旋转四元数 X
512~639        rot_y[128]                 旋转四元数 Y
640~767        rot_z[128]                 旋转四元数 Z
768~895        rot_w[128]                 旋转四元数 W
896~1023       scale_x[128]               X 缩放
1024~1151      scale_y[128]               Y 缩放
1152~1279      scale_z[128]               Z 缩放
1280~1407      vel_x[128]                 X 速度
1408~1535      vel_y[128]                 Y 速度
1536~1663      vel_z[128]                 Z 速度
...            angVel_*, force_*, ...     角速度、力、力矩等
...            invMass, restitution, ...  质量倒数、弹性系数、摩擦系数等
```

ArkTS 侧读取并同步到 3D 节点：

```typescript
// 文件: ets/core/scene3D/PhysicsSystemManager.ets - updateNodeData()
let dataView = new Float32Array(buffer);
// 同步位置
node.position.x = dataView[id];                          // offset +0
node.position.y = dataView[id + this.capacity];          // offset +128
node.position.z = dataView[id + this.capacity * 2];      // offset +256
// 同步旋转
node.rotation.x = dataView[id + this.capacity * 3];      // offset +384
node.rotation.y = dataView[id + this.capacity * 4];      // offset +512
node.rotation.z = dataView[id + this.capacity * 5];      // offset +640
node.rotation.w = dataView[id + this.capacity * 6];      // offset +768
// 同步缩放
node.scale.x = dataView[id + this.capacity * 7];         // offset +896
node.scale.y = dataView[id + this.capacity * 8];         // offset +1024
node.scale.z = dataView[id + this.capacity * 9];         // offset +1152
```

#### 3.3.3 自定义 Shader 材质绑定

对于需要将 2D 图像直接贴到 3D 网格的场景，系统支持自定义 Shader：

```typescript
// 文件: ets/core/scene3D/Utils.ets
NodeUtil.attachShader(
  node, shaderName, $rawfile('shaders/Myshader/myshader.shader'),
  factory, "MyMATERIAL" + shaderName, 'Image' + shaderName, imageUri
);
```

该方式通过 `alphaCutoff = 0.5` 实现透明度裁切，去除黑边以实现圆角外形，使 2D 图像在 3D 中按网格几何体渲染。

### 3.4 视差计算

#### 3.4.1 视差倾斜原理

当 2D UI 组件在 3D 相机视锥体中偏离中心位置时，会产生自然的透视变形效果。这一效果由 **视差倾斜 (Parallax Tilt)** 实现：

```
        相机 (0, 0, -distance)
              │
              │  视线方向
              ▼
              ● ← 偏离中心的 UI 组件 (offsetX, offsetY, 0)
```

核心公式（`PerspectiveTransform.ets`）：

```typescript
// 视差倾斜角度：相机看向偏移位置时的自然倾斜
tiltX = atan2(offsetY, distance);       // X 轴倾斜
tiltY = -atan2(offsetX, distance);      // Y 轴倾斜（方向相反）
```

#### 3.4.2 透视因子与透视增强

```typescript
// 基础透视因子
basePerspectiveFactor = tan(fovy / 2) / distance;

// 透视增强因子：边缘位置透视效果更强
// 线性插值，中心为 1，边缘为 2
perspectiveBoost = 1 + (distToCenter / maxOffset);

// 应用增强后的透视因子
p = basePerspectiveFactor * perspectiveBoost;
```

#### 3.4.3 4×4 变换矩阵构建

完整的透视变换矩阵组合顺序为：**P × Rz × Rx × Ry × T**（透视 × Z旋转 × X旋转 × Y旋转 × 平移）：

```typescript
// 文件: ets/core/math/PerspectiveTransform.ets - calculateTransformMatrix()

const combinedRotY = rotation.y + parallaxTilt.y;
const combinedRotZ = rotation.z;

// 计算旋转矩阵元素
const cosX = Math.cos(combinedRotX);  const sinX = Math.sin(combinedRotX);
const cosY = Math.cos(combinedRotY);  const sinY = Math.sin(combinedRotY);
const cosZ = Math.cos(combinedRotZ);  const sinZ = Math.sin(combinedRotZ);

// 应用透视增强
const p = basePerspectiveFactor * perspectiveBoost;

// 4×4 矩阵（列主序）
// 旋转部分
m00 = cosY * cosZ + sinX * sinY * sinZ;
m01 = -cosX * sinZ;
m02 = sinY * cosZ - sinX * cosY * sinZ;
m03 = p * m02;  // 透视分量

m10 = cosY * sinZ - sinX * sinY * cosZ;
m11 = cosX * cosZ;
m12 = sinY * sinZ + sinX * cosY * cosZ;
m13 = p * m12;  // 透视分量

m20 = -cosX * sinY;
m21 = sinX;
m22 = cosX * cosY;
m23 = p * m22;  // 透视分量

// 平移分量
m30 = offset.x;
m31 = offset.y;
m32 = -cameraDistance;
m33 = 1;
```

该矩阵使得 2D UI 的旋转能够符合 3D 物体旋转的视觉效果，在卡片翻转、倾斜等场景中产生正确的透视变形。

void step(float dt) {
    // 阶段 1: 碰撞对检测
    detectCollisions();           // O(n²) 遍历，调用 CollisionDispatch
    
    // 阶段 2: 生成接触点
    buildContacts();              // 法线/穿透深度/接触点位置
    
    // 阶段 3: 碰撞响应求解
    solveContacts();              // 冲量法求解碰撞响应（法向冲量 + Coulomb 摩擦）

    clampVelocity(dt);            // SAFETY_FACTOR = 0.4，限制最大速度
    
    // 阶段 6: 位置修正
    positionalCorrection();       // k_slop = 0.01, percent = 0.8，修正穿透
    
    // 阶段 7: 位置积分
    integratePosition(dt);        // 四元数旋转更新
}

#### 4.1.4 自适应子步长

为防止高速物体穿透，系统根据速度与物体尺寸动态计算子步数：

```cpp
int PhysicsSystem::computeSubSteps(float dt) {
    int maxSubSteps = 0;
    for (uint32_t i = 0; i < count; i++) {
        if (isStatic[i]) continue;
        float velocity = std::sqrt(vel_x[i]*vel_x[i] + vel_y[i]*vel_y[i] + vel_z[i]*vel_z[i]);
        float minExtent = std::min({extent_x[i], extent_y[i], extent_z[i]});
        int subSteps = static_cast<int>(std::ceil(velocity * dt / minExtent));
        maxSubSteps = std::max(maxSubSteps, subSteps);
    }
    return std::min(std::max(maxSubSteps, 1), 8);  // 最大 8 子步
}
```

### 4.2 碰撞检测算法

#### 4.2.1 碰撞分发矩阵

系统采用函数指针分发矩阵实现不同形状组合的碰撞检测：

```cpp
// 文件: cpp/physics/physics/collision.h
class CollisionDispatch {
public:
    static CollisionFunc table[SHAPE_COUNT][SHAPE_COUNT];
    
    static bool dispatch(const PhysicsSystem& physics, const uint32_t A, const uint32_t B) {
        return table[physics.shapeType[A]][physics.shapeType[B]](physics, A, B);
    }
};
```

当前支持的形状组合：

| 碰撞对 | 检测方法 | 算法复杂度 |
|--------|----------|------------|
| Sphere ↔ Sphere | 距离比较 `d² < (r1+r2)²` | O(1) |
| OBB ↔ OBB | SAT 分离轴定理（15 个分离轴） | O(1) |
| Sphere ↔ OBB | 球心到 OBB 最近点距离 | O(1) |
| OBB ↔ Sphere | 同上（对称） | O(1) |

#### 4.2.2 OBB-OBB 碰撞：SAT 分离轴定理

OBB（定向包围盒）碰撞检测使用 **Separating Axis Theorem (SAT)**，需检测 15 个潜在分离轴：

```
15 个分离轴：
├── A 的三个局部轴 (3)
├── B 的三个局部轴 (3)
└── A 的轴 × B 的轴的叉积 (3×3 = 9)
    └── 排除近似平行的情况
```

对每个分离轴：
1. 将两个 OBB 投影到该轴上
2. 计算投影区间的中心距和半宽和
3. 如果中心距 > 半宽和 → 存在分离轴 → 无碰撞
4. 如果所有 15 个轴都无分离 → 碰撞

#### 4.2.3 接触点生成

碰撞发生后，系统生成接触点用于后续响应求解：

```cpp
// 文件: cpp/physics/physics/collision.h
struct Contact {
    uint32_t bodyA, bodyB;      // 碰撞双方的 ID
    Vector3 normal;              // 碰撞法线（从 A 指向 B）
    float penetration;           // 穿透深度
    Vector3 contactPoint;        // 接触点位置
};
```

接触点生成采用 **参考面-入射面方法**，对穿透顶点进行平均处理以获得稳定的接触点。

#### 4.3.3 速度钳制防穿透

```cpp
void PhysicsSystem::clampVelocity(float dt) {
    for (uint32_t i = 0; i < count; i++) {
        if (isStatic[i]) continue;
        float vx = vel_x[i], vy = vel_y[i], vz = vel_z[i];
        float speed = std::sqrt(vx*vx + vy*vy + vz*vz);
        float maxSpeed = std::min({extent_x[i], extent_y[i], extent_z[i]}) / dt * SAFETY_FACTOR;
        if (speed > maxSpeed) {
            float scale = maxSpeed / speed;
            vel_x[i] *= scale;
            vel_y[i] *= scale;
            vel_z[i] *= scale;
        }
    }
}
```

`SAFETY_FACTOR = 0.4` 确保单帧移动距离不超过物体最小尺寸的 40%，有效防止高速穿透。

## 5. 核心技术三：3D交互融合机制

### 5.1 三维空间中的2D交互拾取

#### 5.1.1 射线检测技术概述

用户通过 2D UI 的点击/触摸操作选中 3D 物体，系统通过 **射线检测 (Raycast)** 将 2D 屏幕坐标转换为 3D 空间中的射线，检测与场景中物体的相交关系。

#### 5.1.2 三类射线相交测试

系统实现了三种射线-几何体相交检测算法，根据物体形状类型自动选择：

**① 射线-AABB 检测（Slab 方法）**

适用于未旋转的轴对齐包围盒，性能最优：

```cpp
// 文件: cpp/physics/physics/include/raycast.h
inline bool raycastAABB(
    const Vector3& origin,
    const Vector3& dir,
    const Vector3& center,
    const Vector3& halfExtent,
    double& tmin,
    double& tmax
) {
    tmin = 0.0;
    tmax = FLT_MAX;
    
    Vector3 bmin = center - halfExtent;
    Vector3 bmax = center + halfExtent;
    
    for (int i = 0; i < 3; i++) {
        double o = origin[i];
        double d = dir[i];
        
        if (std::abs(d) < 1e-8) {
            // 射线平行于 slab
            if (o < bmin[i] || o > bmax[i]) return false;
        } else {
            double t1 = (bmin[i] - o) / d;
            double t2 = (bmax[i] - o) / d;
            if (t1 > t2) std::swap(t1, t2);
            tmin = std::max(tmin, t1);
            tmax = std::min(tmax, t2);
            if (tmin > tmax) return false;
        }
    }
    return true;
}
```

**② 射线-OBB 检测（局部空间变换 + Slab）**

适用于旋转后的包围盒，需先变换到局部空间：

```cpp

```

**③ 射线-Sphere 检测（二次方程求解）**

适用于球形包围盒，解析解最快：

```cpp
inline bool raycastSphere(
    const Vector3& origin,
    const Vector3& dir,
    const Vector3& center,
    float radius,
    double& t
) {
    Vector3 oc = origin - center;
    double a = dir.dot(dir);
    double b = 2.0 * oc.dot(dir);
    double c = oc.dot(oc) - radius * radius;
    
    double discriminant = b * b - 4.0 * a * c;
    if (discriminant < 0) return false;
    
    double sqrtDisc = std::sqrt(discriminant);
    double t0 = (-b - sqrtDisc) / (2.0 * a);
    double t1 = (-b + sqrtDisc) / (2.0 * a);
    
    if (t0 > 0) { t = t0; return true; }
    if (t1 > 0) { t = t1; return true; }
    return false;
}
```

#### 5.1.3 射线检测处理流程

```cpp
// 文件: cpp/physics/physics/physicalSystem.cpp - processRaycast()
void PhysicsSystem::processRaycast(float touchX, float touchY) {
    // 步骤 1: 构建射线
    Vector3 virtual_pos = (up * touchY + right * touchX * ratio) * (-cameraPos.z * tan(fov/2));
    Vector3 rayDir = (virtual_pos - cameraPos).normalized();
    
    // 步骤 2: 遍历所有物体，寻找最近命中
    uint32_t closestId = capacity;
    double closestDist = FLT_MAX;
    
    for (uint32_t i = 0; i < count; i++) {
        if (isStatic[i]) continue;
        double t = FLT_MAX;
        bool hit = false;
        
        switch (shapeType[i]) {
            case SHAPE_BOX:
                hit = raycastOBB(rayOrigin, rayDir, 
                    {pos_x[i], pos_y[i], pos_z[i]},
                    {rot_x[i], rot_y[i], rot_z[i], rot_w[i]},
                    {extent_x[i], extent_y[i], extent_z[i]}, t);
                break;
            case SHAPE_SPHERE:
                float radius = std::max({extent_x[i], extent_y[i], extent_z[i]});
                hit = raycastSphere(rayOrigin, rayDir,
                    {pos_x[i], pos_y[i], pos_z[i]}, radius, t);
                break;
        }
        
        if (hit && t < closestDist) {
            closestDist = t;
            closestId = i;
        }
    }
    
    // 步骤 3: 返回命中结果
    if (closestId != capacity) {
        eventResults.push_back({
            .type = EventType::RAYCAST_REQUEST,
            .nodeId = closestId,
            .status = 1,
            .data = { (double)closestId, closestDist, ... }
        });
    }
}
```

  private readQueues: EventCommand[][] = [[], [], []];

## 6. 阴影渲染方案决策

### 6.1 问题背景

在传统 2D 平面 UI 中，阴影效果通常通过控件的 `shadow` 属性实现——这是一种伪阴影，不考虑纵深关系，所有阴影效果相同。但在 2D/3D 融合场景中，加入了纵深的空间关系后，传统 `shadow` 属性无法带来正确的阴影效果——2D 控件看起来像是与 3D 空间之间隔了一层屏幕。

因此，阴影效果必须交由 3D 渲染管线来实现，以达到 2D 内容向 3D 物体投射阴影的效果。

### 6.2 方案一：2D 图像通过 3D 管线渲染

#### 6.2.1 方案描述

将 2D UI 的渲染结果（截图/帧缓冲区）作为纹理贴到特制的 3D Mesh 上，使其完全按照 3D 管线的方式渲染：

```
2D UI 渲染 → 屏幕截图获取图像 → 自定义 Shader 材质 → 贴到 3D Mesh → 3D 管线渲染
```

#### 6.2.2 实现细节

系统已实现这一方案的验证版本：

```typescript
// 文件: ets/core/scene3D/GlobalSceneProxy.ets - addImage()
// 通过 URI 加载图像并绑定到材质的 BASE_COLOR_Image
let sceneImageParameter: SceneResourceParameters = {

  uri: imageUri
};
let image = await factory.createImage(sceneImageParameter);
material.baseColor.image = image;
material.alphaCutoff = 0.5;  // 透明度裁切，实现圆角外形
```

该方案从理论上可以完美实现 2D 和 3D 的统一——将 2D 绘制过程视作在 3D 物体表面绘制的过程，碰撞和光影完全按照 3D 管线处理。

#### 6.2.3 局限性分析

| 局限性 | 详细说明 | 影响程度 |
|--------|----------|----------|
| **UI 事件系统不兼容** | 2D UI 的点击依赖于 UI 树的事件分发机制，转到 3D 后必须设计一套基于射线检测的 UI 拾取系统，且无父子级关系 | 🔴 高 |
| **无法实时刷新** | 每次必须等待对应的 UI 组件绘制结束，再通过 CPU 传递给 GPU，无法做到实时刷新，仅适用于静态图像展示 | 🔴 高 |
| **跨管线图像传递不可行** | Graphics3D 依赖文件形式输入（URI → 文件系统检索 PNG/JPG），无法直接接受 ArkUI 传递的图像 buffer | 🔴 高 |
| **渲染顺序栅栏** | 2D 和 3D 的 GPU 渲染需要顺序栅栏以避免渲染资源竞争，涉及两个系统的修改 | 🟡 中 |

**探索结论**：我们花费了一个月的时间研究了鸿蒙 Graphics3D 的结构，得出的结论是：理论上可行，但需要 ArkUI 渲染系统留出接口传递图像 buffer 给 Graphics3D 渲染管线，这涉及两个系统级的修改以及渲染顺序栅栏的处理，不是我们在有限时间和人手范围内能够完成的。

### 6.3 方案二：保留 2D UI 原生渲染 + 3D 替身同步（最终选择）

#### 6.3.1 方案描述

保留 2D UI 的原生渲染管线，在 3D 空间对应位置渲染一个相应大小的 3D 平面替身，通过信息联通实现两者的同步：

```
2D UI (ArkUI 渲染)  ←─坐标/旋转/缩放同步──→  3D Proxy Plane (ArkGraphics3D 渲染)
```

需要同步的信息量很少：从像素图片减少为 UI 的二维坐标和 3D 物体的坐标同步。

#### 6.3.2 方案优势

| 优势 | 说明 |
|------|------|
| **全套 2D 触摸事件保留** | 2D UI 保持完整的 ArkUI 事件分发机制，无需重新实现拾取逻辑 |
| **3D 阴影效果独立处理** | 3D 替身节点可以独立接收/投射阴影，碰撞方案由 3D 层自行处理 |
| **同步数据量极小** | 仅需传输位置/旋转/缩放（~9 个 float），而非帧缓冲区图像数据 |
| **架构兼容性好** | 与现有 ArkUI + ArkGraphics3D 双管线架构完美适配 |

#### 6.3.3 方案劣势与应对

| 劣势 | 影响 | 应对策略 |
|------|------|----------|
| **2D UI 表面无法被投射阴影** | 3D 物体的阴影无法投射到 2D UI 表面 | 可接受——在 UI 界面中不受控制的阴影可能影响阅读性 |
| **基于图层的渲染顺序** | 3D 物体不能渲染在 2D UI 前面 | 可接受——3D 物体自由渲染在 2D UI 前面可能带来额外遮挡问题 |
| **前后关系控制受限** | 开发者无法自由控制 3D 物体在 2D UI 的前后关系 | 可通过图层变换技巧解决——让开发者通过调整 Z 深度和图层顺序自由控制 |

#### 6.3.4 最终决策

**选择方案二**。该方案在保留 2D 交互体验的同时获得了 3D 阴影效果，与现有架构的适配性远优于方案一。其劣势在实际应用场景中均可接受或通过变通方案解决。

### 6.4 碰撞体同步机制

无论采用哪种阴影方案，碰撞体的数据处理方式是统一的：

```
2D UI 组件的碰撞体数据
    │
    ▼
┌─────────────────────────────────────┐
│  创建 3D Mesh 碰撞体 (Proxy Node)    │
│  形状: AABB (Box) 或 Sphere           │
│  尺寸: 与 2D UI 组件对应              │
│  位置: 与 2D UI 同步                  │
└──────────────────┬──────────────────┘
                   │
                   ▼
┌─────────────────────────────────────┐
│  C++ 物理引擎进行碰撞检测             │
│  碰撞结果通过 FloatBuffer 返回        │
└──────────────────┬──────────────────┘
                   │
                   ▼
┌─────────────────────────────────────┐
│  2D UI 响应碰撞结果                  │
│  (如：位置调整、物理动画)              │
└─────────────────────────────────────┘
```

**核心原则**：碰撞体数据是无法避免的，必然要为 2D 的 UI 组件创建碰撞体。在两种阴影实现方案中，我们均使用 3D 中的 Mesh 碰撞检测来实现，通过信息数据的同步实现 2D UI 的响应。
